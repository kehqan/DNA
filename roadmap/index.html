Milestone 1 — Azure shell + authentication

No AI execution. All tools present as prompt-builders with Copilot handoff.

Infra setup · Weeks 1–2

  • Provision Azure Static Web App
  • Connect repo, configure CI/CD pipeline
  • Staging and production environments established

Entra ID SSO · Weeks 1–3

  • Integrate RFE/RL Entra ID for org-wide login
  • Role-based access control configured
  • Session handling, token management
  • Staff sign in with existing RFE/RL credentials — no new accounts

Feature migration · Weeks 2–5

Tools are ported with full UI but AI calls disabled. Each tool generates a prompt that users copy and hand off to Copilot — real editorial value during testing, not dead stubs.

Wave 1 · Weeks 2–3

  • Morning Briefing
  • Memory Hunter

Wave 2 · Weeks 3–4

  • Meeting Recap

Wave 3 · Weeks 4–5

  • Fact-Check Assistant
  • BiasEctor

5 tools live in Azure by end of week 5. Image Authenticity Check is introduced in Milestone 2 alongside AI activation.

Testing gate · Weeks 5–7

Closed beta with internal editorial staff. Goal is auth friction, UX clarity, and navigation fit with real workflows.

Gate passes when:

  • No blocking auth/login issues
  • All 5 M1 tools accessible and generating correct prompts
  • At least one cross-service language team has completed a test session
  • Feedback reviewed and critical issues resolved

Milestone 2 — AI API activation

Live AI execution. Azure OpenAI behind Key Vault + Managed Identity.

API infrastructure · Weeks 7–8

  • Azure OpenAI Service provisioned
  • API key secured in Azure Key Vault
  • Managed Identity configured (no secrets in code)
  • Azure Functions wired per tool — one function per tool endpoint
  • End-to-end test on staging before production unlock

Tool activation · Weeks 9–10

  • Submit buttons activated across all 5 M1 tools
  • Image Authenticity Check introduced here — requires AI, built and activated in M2
  • AI responses returned in-app — no Copilot handoff needed
  • Response quality reviewed against Copilot Studio prompt baselines
  • Error handling and fallback states confirmed

Broader rollout · Weeks 11–12

  • Language services onboarded progressively
  • Usage logging active
  • AI Opportunity Report feedback loop open to staff
  • Known issues from testing gate resolved in production

Key decisions and constraints

Tools stay as prompt-builders in M1, not disabled stubs.
The copy-to-Copilot handoff means testers get real value in M1 and editorial feedback is grounded in actual use.

Entra ID integration is the highest-risk item in M1.
Two weeks allocated but org-level auth integrations often expand. If auth slips, feature migration shifts accordingly.

M2 is sequenced: Key Vault first → activation → rollout.
All 6 tools are not unlocked on the same day the API key lands.

AI provider decision must be confirmed before Week 7.
Azure OpenAI keeps data within the Azure boundary. Anthropic Claude requires external inference approval. Flag to management by end of Week 4.

Risks

Risk Likelihood Mitigation
Entra ID SSO integration delays Medium Start auth in week 1, parallel with infra setup
User testing gate extends past week 7 Medium Gate criteria defined upfront; partial pass possible
AI provider decision not resolved before week 7 Low–Medium Flag to management by end of week 4
Azure OpenAI quota / provisioning delays Low Request provisioning at start of M1, not M2
